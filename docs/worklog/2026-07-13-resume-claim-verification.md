# Worklog — 이력·포트폴리오의 과장을 커밋으로 검증해 걷어내다 · 2026-07-13

## 요약 (TL;DR)
- **문제**: 면접관이 근식님을 실제 경력과 다르게 이해했다. 공개 이력서와 포트폴리오에, 실제로 한 일보다 부풀려진 표현이 섞여 있었다.
- **한 일**: 프로젝트마다 실제 기록(코드 저장소의 커밋과 설정 파일)을 하나씩 대조해, 증명되는 것만 남기고 나머지는 걷어냈다.
- **지금**: 공개 사이트의 이력과 포트폴리오가 모두 실제 기록과 일치한다. 수정본은 배포까지 반영됐고, 라이브에서 확인했다.
- **남은 결정**: 없음.

## 한 일 (What we did)

시작은 나니아랩스 1차 인터뷰 준비였다. 준비자료를 만들다 근식님이 "면접관이 나를 랜드북 MSA를 처음부터 설계한 사람으로 알더라"고 짚었다. 그 한마디가 이력 전반의 사실성을 점검하는 작업으로 이어졌다.

랜드북부터 봤다. 랜드북은 인증·결제 같은 기능이 각각의 저장소로 나뉜 구조(MSA)인데, 그 저장소들의 생성 날짜가 모두 근식님 합류(2023년) 이전이었다. 즉 구조를 설계한 게 아니라, 이미 있는 구조에 들어와 서비스를 개발·운영한 것이다. 표현을 사실에 맞게 고쳤다.

다음은 기술 스택이었다. 이력에 "Kafka로 무거운 작업을 격리했다"고 적혀 있었지만, 랜드북 저장소의 의존성 파일에는 Kafka도 Redis도 없었다. 반대로 근식님이 주도한 다른 제품(PlanNext.AI)의 저장소에는 Kafka가 실제로 들어 있었다. 그래서 랜드북에서는 빼고, PlanNext에서는 남겼다.

마지막으로 커밋 수와 성과 서술을 훑었다. 여러 프로젝트의 커밋 수가 실제와 달랐고, 한 데이터 파이프라인(Realty)은 프로젝트 전체의 특징을 근식님 개인 성과처럼 적고 있었다. 근식님의 실제 기여(수집 안정성과 재개 로직)로 초점을 옮겼다.

## 결정과 왜 (Decisions & why)

| 결정 | 버린 대안 | 왜 |
|------|----------|----|
| 랜드북을 "이미 MSA인 환경에 합류해 개발·운영"으로 표기 | "MSA를 설계" 유지 | 서비스 저장소 6개가 전부 근식님 합류(2023) 전에 만들어졌다. 설계자가 아니라 개발·운영자다. |
| 랜드북 이력에서 Kafka·Redis 삭제 | 그대로 유지 | 랜드북 저장소 의존성 파일에 Kafka·Redis가 없다. 근거 없는 스택은 쓰지 않는다. |
| Kafka·Redis는 PlanNext 맥락에서만 유지 | 모든 곳에서 삭제 | PlanNext의 `plannext-engine-consumer` 저장소에 `spring-kafka`가 실재하고, 근식님이 관련 설정 커밋을 직접 남겼다. |
| 커밋 수를 실측값으로 교체 | 기존 표기 유지 | MIRIVA·Ground Control은 실제보다 적게, garo·zippit은 크게 적혀 있었다. Nova는 회사 저장소 수치를 공개 저장소 것처럼 써서 오해를 낳았다. |
| Realty를 "크롤러 안정성·재개 기여"로 재작성 | atomic swap·무중단 배포를 성과로 유지 | 근식님 커밋 13개의 실제 내용은 수집 안정성과 중단 재개다. atomic swap 같은 무중단 배포는 다른 기여자의 몫이다. |
| Proof 디자인을 private 저장소로 이동 | 공개 포트폴리오에 커밋 | 미출시 제품이라 공개 노출을 피하되 버전관리는 유지해야 한다. |

## 배운 것 (Learned)
- 이력서와 포트폴리오, 프로필의 사실 주장은 커밋과 코드로 검증한 뒤에만 쓴다. (이번에 `/learn`으로 운영 규칙에 반영)
- 프로젝트 전체의 특징을 본인 기여로 뭉뚱그리지 않는다. 본인 커밋으로 증명되는 몫만 본인 성과로 쓴다.
- 커밋 수는 저장소를 특정해서(개인 대 회사, 본인 대 전체) 정확히 밝힌다. 뭉뚱그리면 오해를 부른다.

## 세션 흐름 (How it moved)
1. 나니아랩스 1차 인터뷰 준비자료를 만들었다(전략 문서, 모의 문답, 실시간 참조용 웹페이지).
2. "면접관이 MSA를 설계한 줄 안다"는 지적에서, 랜드북 저장소의 생성 날짜와 커밋을 실측했다.
3. Kafka·Redis 주장을 의심해 의존성 파일을 확인했고, 랜드북엔 없고 PlanNext엔 있음을 갈랐다.
4. 전 프로젝트의 커밋 수를 로컬 기록과 원격 API로 실측해 바로잡았다.
5. Realty를 검증해, 근식님 실제 기여인 크롤러 안정성으로 초점을 옮겼다.
6. Proof 디자인 시스템과 목업을 private 저장소로 옮기고 공개 저장소를 정리했다.
